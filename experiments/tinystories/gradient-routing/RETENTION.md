# Capture and retention policy
Adopted during qualification, 2026-11-18 15:05 UTC; a storage lifecycle amendment, not a change in scientific endpoints or the already frozen qualification's retention setting.

1. Before each arm, decide which physical generations are actually necessary for restart, temporal metrics and the final comparison. Predeclare at most the current recovery generation and its predecessor, any specifically named sparse temporal slices, and the final matched models unless an experiment requires more. Use native `checkpoint.keep_periodic`, generation pointers and documented retention modes; do not install a separate checkpoint janitor.
2. At each required milestone, record actual valid targets, training/dev CE, clock, loss mask, schedule state, file identities, raw metric numerators/denominators, exact probe/sample hashes and any generation-panel outputs. Mark temporal analysis pending or complete explicitly. Avoid a checkpoint at every plotting point where a measured scalar or evaluated prediction is enough.
3. At completion, preserve **both** final baseline and treatment checkpoints for the selected comparison, required status/manifests and statistical tables, clean source/config/data/tokenizer identities and any exceptional frozen probe checkpoint whose analysis cannot otherwise be reproduced. Do not equate a checkpoint hash in a text file with a recoverable state.
4. For qualification, retain the step-4 restore point until its child and the uninterrupted comparison have verified state equality. Then retain final comparison states per the owner decision; propose retirement of nonfinal checkpoint payloads and temporary prepared copies only after verifying dependencies and a byte-accounted inventory. Keep the prepared source required by a future comparison and all failed-attempt evidence.
5. Inventory each candidate by exact run/generation, unique physical bytes (hardlinks counted once), current pointers and downstream consumers, verified archive/copy identity and the information lost by deletion. Distinguish reproducible temporary outputs from unique optimizer/data/RNG state. Deletion without an equivalent verified recoverable copy needs an explicit owner-approved batch; never prune other workloads or rewrite manifests to hide missing generations. Compact an OS virtual disk only as a separate user-directed operation.
6. Report measured live working-set/disk high-water marks and post-capture retained bytes, not total filesystem size or sparse virtual-disk capacity. Release a claim only after the workload and analysis/process receipts are terminal. Keep small provenance for every attempt, even a systematic failure.
