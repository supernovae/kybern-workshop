# Reproduce
Use the two local research branches and their recorded base revisions, not the unmodified public main. The files are being prepared locally; no remote branch is implied. Lockfile and environment pins belong to Model Lab. Archive source-revision and dirty patch identities with every measurement. See [prior studies](EVIDENCE.md), [historical paired analysis](historical-reanalysis.md) and [the synthetic fixture](mechanisms.md).

**Offline checks already measured:** From the Lab root, with the existing staged CPU runtime selected via `UV_PROJECT_ENVIRONMENT`, `UV_OFFLINE=1 PYTHONPATH=src uv run --locked --no-sync pytest -n 0 -q tests/test_full_width_output_head.py tests/test_gradient_projection.py tests/test_routing_mechanisms.py`. These are small correctness checks, not a training reproduction.

**Community training adaptation (not launched as part of the ROCm qualification).** The [existing CPU microlab](../../../examples/tinystories-microlab/README.md) is a practical baseline: width 128, two untied layers, vocab 4096, 20,000 train and 500 development stories, 1,500 updates, 3.072M nominal positions. This is a separately identified experiment, not a claim to replicate the published 58.9M result. Run the microlab workspace and source/tokenizer preparation steps with native Lab, using pinned source release and digest verification; use local pre-staged assets only on an offline qualification host. Copy the two `reference-*.yaml` deltas in this directory beside the microlab's `policy.yaml`. From that microlab workspace:

```sh
klab config validate declarations/run.yaml --kind run
klab try reference-frozen.yaml --vs declarations/run.yaml --config policy.yaml --backend cpu
klab try reference-c4.yaml --vs declarations/run.yaml --config policy.yaml --backend cpu
klab report TRY_ID --json
```

Replace TRY_ID with the value produced by the relevant try. Use two independent run labels; do not report seed 1 as confirmation. To run a paired sweep within a new explicit budget, use the native sweep schema with ordinary `declarations/run.yaml`, a single `points` entry `{model.output_head_parameterization: identity_trainable}`, and the frozen paired seeds. Do not initiate that sweep on this research host from this document. Frozen control can first be demonstrated by the exact one-step unit test (far less costly). The parent microlab reports about four minutes per arm on its 48-thread CPU for a *different rank treatment*. C4 runtime must be measured; no extrapolation to the workstation GPU or a CI claim. Holding initialization, task, rank and CE fixed does not match AdamW's factor-wise moments, effective update or FLOPs.

**Archive-compatible reporting checklist:** Supply both heads' initial tensor hashes, backbone and effective W; exact source commit+patch, physical GPU/runtime/dtype (or CPU), tokenizer bytes and mapping hash, source revision, split/file hashes and overlap, actual valid training targets and unique stories; independent RNG streams and data order; optimizer/betas/decay/clip/warmup and effective update; checkpoint and restart policy; eval split status, score weighting and common threshold; clean and instrumented timings, cost of calibration, effective CPU/GPU device time, wall time and peak memory. Provide individual paired deltas and record every attempted config, excluded or censored result. Quote ceiling and measured usage separately. Report residual norm and retained energy separately for raw and centered effective W. A retained-energy increase without improved held-out learning is not an efficiency gain.

A fresh untouched test set has not been established for the local staged data. Confirmation means freezing treatment and paired seeds and evaluating predeclared development/independent test roles; it does not turn a repeatedly used validation set into a test. No corpus text, weights, optimizer states, credentials, hosted dashboard, or publishing is included here.

For the qualification target/wall figures, use the row-level qualification-evaluations.csv without interpolation: horizontal axes are verified valid_training_targets or elapsed_to_evaluation_seconds; vertical axis is development_nll_nats. Coincident points should coincide; there is no confidence band for one seed.
